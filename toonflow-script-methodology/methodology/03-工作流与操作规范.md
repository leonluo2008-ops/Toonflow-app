# 工作流与操作规范

> 🚦 **本页 = 剧本工作台的操作规范。** 启动新项目、规划推进、接力交接时读本页；审计清单见「审计规范与清单」，写作铁律见「创作方法论」，模板见「模板库」。

## 0. 工作台使用原则
- **主页是总控台**：放流程、模板、规范、索引和复盘，不直接堆单个作品正文。
- **每个作品一个项目工作页**：用于承载 L0–L3、项目规则、接力规范、章节正文入口和审计记录。
- **项目页面归属规范**：先在剧本项目库建项目记录（即项目主页），所有作品页都挂在该记录页之下；工作台根页只放体系、模板、规范、索引与复盘，**不得直接挂任何具体作品页**。项目记录页之下采用统一浅层结构：
  - **项目工作页**：控制台，放 L0–L3 / 项目规则 / 接力规范 / 当前正文台账 / 审计记录；是每次必读的「说明书」。
  - **标准剧本大纲页**：对外交付稿。
  - **交接报告页**：冷启动简报，固定一份、覆盖维护（仅当用户要求时整页重写，不留历史版本、不追加）；新开对话窗口先读它即可快速接手。
  - **每季一个「第 N 季」容器页**：该季全部章节正文页都放进对应季容器页内，与工作页、标准大纲平级。
  - **正文按季归容器、不挂工作页**：章节正文页一律归入所属「第 N 季」容器页，不得直接挂在项目工作页之下。
- **每章一个当前正文页**：同章修订直接更新当前页，不新建 v2/v3。
- **每个成熟项目一个标准剧本大纲页**：用于交付、接力、改编和对外查看。
- **阶段完成必须回写**：章节页、项目工作页、标准剧本大纲页三处要同步。

## 2. 标准工作流

> 🚦 **正文闸门**：正文启动前，必须先完成全系列 L2 季总纲、当前季 L2 详细章纲、当前季 L3 全章 beats，并通过架构审计。不能只拆第一章就开始连载。
>
> **框架闸门**：L0–L3 一律**启发式共创**（架构师＝引导者非生成器），逐层「启发→发散→收敛→门禁」、每道门主创显式确认才前进；发散在工作页「框架共创区」、锁定项才提升进正式 L0–L3。**禁止一次性自动产出整套 L0–L3 让主创只做审批。**

### 执行顺序
1. **L1 定魂**：锁系列总内核、主题宣言、主角总弧光、结局方向。
2. **L0 定世界**：设计世界观、角色生态、平台 / 反派系统，让它们服务 L1。
3. **全系列 L2 定路**：每季至少锁住主题、映射核心、主冲突、弧光推进、季末钩子、伏笔。
4. **当前季 L2 拆章**：当前要写的季拆 7–10 章详细章纲。
5. **当前季 L3 拆 beats**：每章拆到 5–7 beats，不只拆第 1 章。
6. **架构审计**：确认全系列方向、跨季伏笔、章节递进、喜剧 / 悲剧比例都稳。
7. **逐章写正文**：审计通过后，才逐章串行写。
8. **双审计（独立子 Agent·强制）**：每章正文写完，必须派生独立的审查子 Agent（Notion 子对话线程）分别做结构审计 + 风格审计；正文可由主控自写或交由执行子 Agent 落地。审查子 Agent 只读不改，只输出 P0/P1/评分与建议；主控判断后在当前页修订，必要时重跑至 P0 清零。
9. **同页修订**：审计未过时，直接修订当前章节页，不新建同章 v2/v3。
10. **回写接力信息**：每次创作或修订后，同步更新项目页接力规范、章节台账、已锁定事实和下一步动作。
11. **标准大纲同步**：阶段完成后，把工作页内容整理到独立标准剧本大纲页。

### 多智能体协同模型（主控 → 执行 → 审查）
- **主控 Agent（与用户对话者）**：诊断当前阶段、规划方案、判断 P0、决定修订与放行；只做调度与裁决，不自审自夸。
- **执行子 Agent（写手层）**：承接主控的 beats / 修订指令落地正文，由主控派生的独立 Notion 子对话线程承担（正文亦可由主控自写）。
- **审查子 Agent（审计层·只读）**：对执行结果做独立交叉验证，分结构审计、风格审计两路；只输出 P0/P1、评分与建议，绝不改文。

> 三层职责边界不得混淆：**执行只写、审查只查、主控只判与改**。审查与执行必须由不同子 Agent 承担，杜绝「自写自审」。

## 6. 接力创作规范
### 接力时必须先读
1. 项目工作页
2. 当前承接章节页
3. 接力创作规范
4. 当前正文台账
5. 已锁定事实
6. 标准剧本大纲页
7. 最近一次审计记录
8. 剧本项目库中的项目记录
9. 剧本风格库中的主风格 / 辅助风格记录

### 接力记录必须包含
| 字段 | 要求 |
|---|---|
| 当前阶段 | 用统一状态枚举，不写模糊的“进行中”。 |
| 下一步动作 | 必须具体到“审计 / 修订 / 写哪章 / 拆哪季”。 |
| 当前承接页 | 必须指向唯一页面。 |
| 前置条件 | 说明下一步开始前必须完成什么。 |
| 禁止动作 | 写清不能跳过、不能新建、不能改乱的部分。 |
| 已锁定事实 | 记录不能被后续创作推翻的设定。 |

## 7. 状态管理规范
### 项目状态枚举
构思中 / 立意共创中 / 框架共创中 / L1 已定 / L0 已定 / 全系列 L2 已定 / 当前季 L3 已定 / 架构审计中 / 正文创作中 / 单章审计中 / 单章修订中 / 当前季已完稿 / 全季一致性审计中 / 全季总修中 / 标准大纲已同步 / 下一季准备中 / 暂停 / 归档
### 章节状态枚举
未拆 L3 / L3 已拆 / 待写正文 / 初稿完成 / 结构审计中 / 风格审计中 / 待修订 / 已修订 / 本章通过 / 归档 · 废稿

## 8. 禁止动作
> ⛔ 这些规则是为了防止长篇项目崩坏。除非用户明确推翻，否则默认严格执行。

- 不得在正文启动前跳过全系列 L2。
- 不得在框架阶段一次性自动产出整套 L0–L3 让主创只做审批：须逐层启发式共创 + 显式门禁。
- 不得只拆第 1 章就开始连载。
- 不得同一章保留多个当前版本；不得用 v2/v3 新页面替代同页修订。
- 不得把章节正文页直接挂在项目工作页之下：正文一律按季归入「第 N 季」容器页。
- 不得让审计 agent 直接改正文。
- 不得在正文中出现“第几章 / 上一章 / 下一章 / 本章 / 读者会看到”等元叙事表达。
- 不得只更新章节正文，不更新接力规范；不得只记录“写到哪”不记录“下一步怎么接”。
- 不得让故事内时间漂移；不得让角色 / 物种体型漂移（体型锁定后抱/背/拖/骑/钻/翻滚/逃跑/战斗须符合物理约束）。
- 不得在送审时漏喂 canon（系列总纲 / 设定落地表 / 已锁定事实 / 前序事实链）。
- 不得对重复误报反复返工：误报一经判定即登记「已知误报清单」、送审必附、命中即跳。
- 不得让核心主题 / 点题越阶提前兑现；不得为满足“每章有金句”强行加戏。
- 不得把某种情绪 / 反应写成定式套话；不得给功能性道具强行加戏；不得为兑现体系强行升格核心字；不得把奇观写成空响。
- 不得把 P0-设计（主题边界 / 核心要素归阶等框架级选择）当硬伤自动判 fail，须标「需主创裁决」。
- 不得把项目专属规则升级成全局规则，除非多项目验证。
- 不得把标准剧本大纲当成草稿堆放区；不得把废稿 / 未确认设定 / 审计争议直接写进标准剧本大纲。
- 不得给「交接报告」留多份历史版本或随意追加：固定单份、仅当用户要求时整页覆盖更新。
