# 审计规范与清单

> 🔍 **本页 = 剧本审计的规范与清单。** 每章正文写完、架构审计、全季一致性审计时读本页。审查子 Agent 的可复用 Prompt 见 `skills/SKILL-剧本审查子Agent.md`；本页提供投喂规范、误报治理、P0 分级与审计清单 A–E。

## 审计执行方式（独立子 Agent·强制）

- 独立审计强制由**独立的审查子 Agent（Notion 子对话线程）**执行，与执行层、主控层分离，不得主控自审自夸；**统一使用自有子 Agent 能力派生子对话线程，禁用 MCP 审计工具**。
- 每章两路并行：一路只做**结构审计**、一路只做**风格审计**，各自独立派生、互不干扰。
- 送审一律投正文全文（不投摘要）；喂给审查子 Agent 的 beats / 上下文措辞须与正文一致，避免摘要用词（如把实物墨迹描写说成「词条点亮」）误导审查产生误报。
- **派生审查子 Agent 时，必须注入「审查子 Agent Prompt」作为其首条指令 / 系统提示词**，并按下方「审计上下文投喂规范」投喂完整上下文，确保口径、检查项、P0 分级与误报处理一致。
- 架构审计走 §A、全季一致性审计走 §E，同样由审查子 Agent 只读执行。

## 审计上下文投喂规范（强制 · 标准上下文防漏）

每次派生审查子 Agent 运行独立审计时，**必须在其首条指令里传入以下完整的标准上下文对象**，缺项会让审查退化为「本章自洽」、漏检跨章冲突：

1. **`project_context` 必带字段**：
   - `project_name`、`genre`、`l1_core`、`l0_world` 等基础设定。
   - `series_l2`：全系列季总纲（**必传，防跨季主题越阶漏检**）。
   - `current_season_l2`：当前季详细章纲。
   - `project_rules`：本项目专属规则及已锁定事实（防体型/时间线漂移）。
   - `forbidden`：禁用词与防越阶限制。
2. **`chapter_context` 必带字段**：
   - `chapter`、`chapter_title`、`chapter_beats`。
   - `existing_draft`：当前正文内容（待审计内容）。
   - 包含前序已锁定事实链，把审计从「本章自洽」升级到「全季自洽」。
3. **`style_rules` 必带字段（风格审计专用，极易漏传）**：
   - `tone`：语调（如：周星驰式悲喜剧）。
   - `narration`：叙事人称视角。
   - `must_have`：必须包含的风格（如喜剧外壳、小人物自嘲、动作替说教）。
   - `anti_patterns`：反模式（如元叙事穿帮、作者旁白说教、核心词过度堆砌）。

- **再创作品特别提示**：经典再创中，必须在 `project_context` 写明本作映射，否则审计员会拿原典判矛盾产生重复误报。

## 误报登记机制（强制 · 治理重复误报）

- 每个项目工作页维护一份「已知误报清单」（写进该项目审计记录区）：登记已被主创判定为误报的模式（如「昵称≠原典物种」「实物墨迹描写≠词条点亮」）。
- 送审必附该清单，审计员命中即跳过、不重复报；主创复核对命中项直接标「误报（不改）」，不返工。
- 同一误报出现第 2 次必须当场登记，避免每章重复打捞。

## P0 分级口径（强制 · 区分硬伤与设计）

- **P0-硬伤**：逻辑 / 设定 / 时间线 / canon 矛盾、事实冲突——必改。
- **P0-设计**：触及框架级设计选择（主题边界、核心要素归阶、风格尺度、点题口径）——标「需主创裁决」，审计员不擅自判 fail，由主创定夺后再动。
- 复核先分流：硬伤进修订队列，设计项进主创决策队列，避免「真问题被误报和设计争议淹没」。

## 主题 / 核心要素归阶校验（强制 · 杜绝提前兑现）

- 每个项目须在工作页维护一张「主题 / 核心要素归阶表」：列明每条主题线索 / 核心母题的归属阶段（哪季 / 哪章兑现、点题、发情感奖励）。
- **规则**：核心主题可「火苗式」提前铺设（埋种子、闪一念），但兑现 / 点题 / 情感奖励必须锁在归属阶段；提前完整点题＝越阶，按 P0-设计处理。
- 逐章结构审计即对照此表校验核心主题落点，防止把后季的成长奖励提前发掉、稀释终局。

## 5. 审计清单

### A. 架构审计
- [ ] L1 是否清楚？
- [ ] L0 是否服务 L1？
- [ ] 全系列 L2 是否有跨季递进？
- [ ] 当前季是否有起承转合？
- [ ] L3 是否每章都有功能？
- [ ] 现实映射是否具体？
- [ ] 主角弧光是否连续？
- [ ] 季末钩子是否能推动下一季？
- [ ] **核心主题 / 要素是否已排好归阶？**（每条主题线的兑现 / 点题落在正确季 / 章，未提前越阶兑现——见「主题 / 核心要素归阶表」）

### B. 正文结构审计
- [ ] 是否承接上一章的事件、情绪、道具或系统提示？
- [ ] **故事内时间是否连贯？**（本章发生在第几日／什么时段／距上章过了多久；“这些天 / 这两天 / 练出的本事”等模糊时间词是否与事件链自洽，不得与“无缝紧接上一章”矛盾）
- [ ] 是否完成本章 L3 beats？
- [ ] **奇观 / 机制是否推动因果？**（不能只做音效、光效、空吼、热闹背景；必须改变环境、选择、阻力或解决方式）
- [ ] **反派反应是否合理？**（发现异常后是否按自身资源和职业逻辑反应；失败是否来自价值观局限 / 机制反噬，而非突然降智）
- [ ] 是否有章末钩子？
- [ ] 是否新增未解释设定？
- [ ] 是否破坏已锁定事实？
- [ ] 道具是否前后连贯？
- [ ] **角色 / 物种体型与动作是否自洽？**（抱起、拖拽、背负、骑乘、钻缝、翻滚、逃跑等动作须符合已锁定体型、力量与受伤状态）
- [ ] 平台 / 反派机制是否一致？
- [ ] 现实映射是否落到具体情节？
- [ ] **是否与前序已锁定事实 / 设定冲突？**（跨章一致性：习性 / 道具 / 称呼 / 时间线须与前几章 canon 一致；送审须已喂前序事实链）
- [ ] **本章核心主题 / 点题是否在其归属阶段？**（提前出现仅可火苗式铺设，不得提前兑现后季的成长奖励）

### C. 正文风格审计
- [ ] 是否保持目标风格？
- [ ] 是否做到动作替说教？
- [ ] 是否有配角反对声？
- [ ] 是否有系统弹窗 / 冷幽默 / 荒诞道具？
- [ ] 是否有“被笑瞬间”？
- [ ] 是否避免大段机制解释？
- [ ] 是否避免元叙事穿帮？
- [ ] **核心词/同一字是否过度堆砌？**（如「观」「格物」「读懂」高频复现导致生硬、阅读发涩；同段同字应控量、换说法，可用：瞄/打量/盯/端详/琢磨/留意等替换「观」）
- [ ] **核心字升格是否压过正常语境？**（核心字 / 母题词只在真正高光处升格；日常视线 / 叙述应用自然说法——正常语境＝最高优先级，不为兑现体系强行升格，否则文绉绉、出戏）
- [ ] **某种情绪 / 反应是否沦为定式套话？**（如「（看 / 观）它怕什么」「怕 / 恐惧」反复贴标签，把角色 / 对象框成单一内核；应改用动作呈现 + 多样化表述，真实强情绪少而精）

> 注：全季一致性审计（§E）走同一套投喂规范与 P0 分级，由审查子 Agent 只读执行，覆盖跨章 canon、时间线、体型、称呼、归阶等全局一致性。
