# 实战复盘与落地参考

> 🧪 本页 = 实战复盘与落地参考。需要回顾为什么会有某条铁律、或需要落地 / 能力边界参考时读本页；日常创作不必加载。

> **给 Claude Code 的说明**：下面是 leon 连续写完整季后沉淀的教训——每一条都是先踩坑、再变成铁律的。这些是 Toonflow 改造时「为什么要这么约束」的依据，也是审计清单 / 禁止动作的来源。

## 《天爪司机》实战复盘

> 🧪 **实战结论**：原体系“架构师 → 写手 → 审计”方向正确，但连续写完整季后发现，真正影响长篇接力的不是能不能写一章，而是能不能稳定维护“唯一正文页、审计闭环、事实台账、标准交付大纲”。

### 1. 一章一页，但只能有一个当前正文页
- **问题**：第 3 章曾同时出现 v1 和 v2，后续接力容易误读旧版本。
- **修正**：每章只保留一个当前正文页。修订必须直接更新该页，不再新建同章 v2/v3。
- **例外**：确需保留旧稿时，必须标注“归档 / 废稿”，并从项目页章节正文区移除。

### 2. 审计必须分成“结构审计”和“风格审计”
- **问题**：单一审计容易漏项。第 4 章出现“第 3 章那只孔雀”这类元叙事穿帮，审计没有及时发现。
- **修正**：每章正文后必须执行两个审计：
  - **结构审计**：检查 L1/L0/L2/L3 一致性、章间承接、伏笔、钩子、现实映射。
  - **风格审计**：检查风格指纹、正文沉浸、喜剧外壳、悲剧内核、禁用表达。
- **规则**：两个审计都没有 P0，才算本章通过。
  - **升级（山海少年实战）**：独立审计统一改由独立审查子 Agent（结构 / 风格两路 Notion 子对话线程）执行，并新增「核心词/同字堆砧」风格检查项——第 3 章「观」字过度复现未被旧审计发现，已纳入风格审计清单。

### 3. 审计只读不改，主调度负责修订
- **问题**：如果审计直接改文，责任边界不清，容易把正文改偏。
- **修正**：审计 agent 只输出问题、等级和建议；主调度综合判断后，再由写手或主调度修订当前页。
- **修订后动作**：必要时重新跑审计，直到 P0 清零。

### 4. 正文沉浸规范必须成为通用检查项
- **问题**：正文里出现“第几章 / 上一章 / 下一章 / 本章 / 读者会看到”等创作层级语言，会破坏小说沉浸感。
- **修正**：所有项目都应加入“正文沉浸检查”。章间承接必须改写为角色当下能感知的时间、事件、道具或系统提示。
- **示例**：不用“第 3 章那只孔雀”，改成“昨天那只孔雀”或“那笔差评”。

### 5. 角色称呼与关系要写成硬规则
- **问题**：第 4–6 章中“老母”“娘俩”等称呼让旺财、母亲、小崽的亲属关系变混乱。
- **修正**：项目页必须维护“称呼规范 / 关系规范”。
- **执行**：正文修订时，不只改当前句，还要把规则写入项目页，防止后续复发。

### 6. 接力创作规范不能只记录“写到哪”
- **问题**：简单写“7 / 7 已完成”无法支持下一次接手。
- **修正**：项目页必须有一个“接力创作规范”区，至少包含当前阶段、下一步动作、当前承接页、每章当前正文页、每章状态与接力要点、已锁定事实、禁止动作、接力前检查清单。

### 7. 工作页与标准大纲页要分离
- **问题**：工作页承载 L0–L3、审计、接力、章节链接，越写越像创作后台，不适合对外交付。
- **修正**：每个成熟项目至少有两类页面：
  - **创作工作页**：放 L0–L3、meta_rules、接力规范、章节正文链接、审计策略。
  - **标准剧本大纲页**：按作品基础信息、卖点、背景、体量、用户定位、对标作品、故事概括、世界观、分季大纲、人物设定整理。

### 8. 审计上下文与误报治理（山海少年实战）
- **问题**：ch5 / ch6 两轮独立复审暴露 4 类系统性毛病——①审计员没拿到 canon，把再创昵称「从从」按《山海经》原典误判为矛盾，连错两章（重复误报）；②只喂本章稿，查不出「逆着风」与前几章「下风口可藏」设定冲突（跨章一致性漏检）；③真矛盾（野果逻辑）与误报（从从）同列 P0，分级混乱；④审计照出框架自身的洞——核心字「自知」本属第四季，却在第一季结尾提前点题兑现（主题越阶）。
- **修正（已写入审计规则）**：①「审计上下文投喂规范」——canon 链（系列总纲 / 设定落地表 / 已锁定事实 / 前序事实链）必投喂；②「误报登记机制」——项目维护已知误报清单、送审必附、命中即跳；③「P0 分级口径」——区分 P0-硬伤（必改）与 P0-设计（需主创裁决）；④「主题 / 核心要素归阶校验」——核心主题可火苗式提前铺、兑现 / 点题锁归属阶段。
- **启示**：审计不只是抓错字，它能照出框架的内在张力；P0-设计这类要交主创裁决，而非自动 fail。

### 9. 金句与奇观机制：从“强塞点题”到“事件自证”
- **问题**：在《山海少年》第 7 章重构中，曾为了补足核心字与金句，把「我没有拳头——我只是把它们一个一个格明白了」塞进追逐 / 对抗段，导致人物在不该停下说理的时刻强行点题；同时把长右沾水写成“吼”和制造声浪，只有表层热闹，不能真正推动事件。
- **修正**：①金句改为宁缺毋滥，点题优先由事件完成；②神兽习性从表层反应升级为“被压住的本性复流”——狸力为土性、长右为水性，水土一合使笼线失稳，场面因果由世界观机制推动，而非靠巧合或噪声。
- **方法论**：先判断“这个奇观改变了什么”。如果没有改变环境、选择、阻力或解决方式，只是让场面更吵更亮，就是无效奇观；如果一句金句不能在人物当下自然发生，就是无效金句。真正的点题应当让读者从结果里明白，而不是让角色替作者念出来。

### 10. 体型与动作物理约束：从“可爱抱宠”到“真实伙伴”
- **问题**：在《山海少年》第 7 章二次重写稿中，从从已在 ch4 被写成“像匹还没长开的小马驹”的幼年鹿蜀，但 ch7 仍多次出现“小满抱着从从奔跑 / 翻滚 / 按在怀里”的动作，把小马驹量级伙伴误写成猫狗型幼崽，造成跨章体型连续性 P0。
- **修正**：明确从从体型动作规则：可贴身跟随、蹭手、低身钻缝、被扶颈 / 牵残网引导；不可被小满抱着连续逃生。正文中改为“贴着肩侧跑、攒残网、压低脆子、贴身避险”等动作。
- **方法论**：任何长篇项目中，角色 / 物种 / 载具体型一旦锁定，就必须进入“物理动作约束”。写动作戏前先问：这个对象有多大？谁能搬动它？它怎么转身、钻缝、被救、逃跑？体型不是外貌描写，而是动作因果的一部分。

### 11. 语言定式 / 道具加戏 / 核心字升格回调（山海少年实战）
- **问题**：《山海少年》第二季 ch1–3 主创通读后发现三类语言 / 分寸毛病——①「怕」沦为定式：「（看 / 观）它怕什么」成反复套话、散落的「恐惧 / 惊恐 / 怯」把神兽框成「以怕为核」，显做作、与正向立意不搭；②笔记本强行加戏：纸质笔记本反复「描出—塞回—攒紧—强调湿」、与核心道具《山海图》功能重叠；③核心字「观」滥用：ch3 把多处日常「看」升格为「观」，生硬、不合正常语境（此前一度被误当作「字脉升格」加分项）。
- **修正**：①情绪 / 反应改用动作呈现（炸毛 / 嗥鸣 / 夹尾）+ 多样化表述（性子 / 门道 / 破绽 / 怎么使劲 / 为什么挣），真实强情绪少而精；②笔记本只在真正记 / 查时出场、每章 1–2 次有功能使用，混乱场景不摆弄，核心道具与配角道具分工；③确立「正常语境＝最高优先级，高于体系升格」——日常一律用「看」，「观」全季至多一处真正高光，宁缺毋滥。同章原地修订、不动结构与 beats。
- **方法论**：①任何被反复使用的情绪 / 认知词都可能退化成定式，把人物 / 对象压成单一标签——用动作与多样化表述破定式；②道具是因果零件不是气氛点缀，只在有功能时出场；③创作体系（字脉 / 母题词升格）服务于自然行文，当升格伤害正常语境的自然度时，正常语境优先、核心字宁缺毋滥。三条已沉淀为方法论 + 风格审计清单项 + 禁止动作。

## 附录 B：在 Notion 里怎么落地

| 体系里的东西 | Notion 载体 |
|---|---|
| 每个系列作品 | 剧本项目库一条记录（即项目主页）；项目工作页、各「第 N 季」容器页、标准大纲页、交接报告页均建在该记录页之下 |
| L0 / L1 / L2 / L3 设计 | 项目工作页里的结构化区块 |
| 每一章正文 | 归入所属「第 N 季」容器页（项目记录页下、与工作页平级）的章节子页，一章一页；不挂在工作页之下 |
| 接力创作状态 | 项目工作页里的接力创作规范 + 当前正文台账 |
| 跨窗口快速交接 | 项目记录页下的「交接报告（最新）」子页：单份覆盖维护的冷启动简报，新窗口先读它再按清单加载 |
| 标准交付材料 | 独立标准剧本大纲页 |
| 项目管理 | 剧本项目库数据库（状态 / 阶段 / 承接页 / 风格 / 下一步） |

## 附录 C：能力边界

> ✅ **能做**：扮演架构师、写手、结构审计、风格审计、标准大纲整理者，在 Notion 里读写页面并维护项目接力。

> ⚠️ **做不到**：直接替代真正的长期后台任务。每次接力需要通过项目工作页、章节页、标准大纲页和审计记录重新建立上下文。
