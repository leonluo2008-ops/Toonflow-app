# 工作方案：在 Toonflow 上升级剧本创作（给 Claude Code）

> 🎯 **本页定位**：一份给 Claude Code 执行的**源码级改造工作方案**。目标——在 Toonflow-app 现有「剧本 Agent」之上，新增/增强流程与子 Agent，把 leon 的成熟剧本方法论（L0–L3 启发式共创 · 三层角色边界 · 双审计 P0 回环 · 创作红线 · 风格指纹）以 toonflow 的结构落地。**先看第二节「边界评估」——这是你要我评估的部分。**

## 一、背景与目标

**已知事实（来自 toonflow 深入理解指南）**：
- Toonflow = **剧本 Agent（scriptAgent）** + **生产 Agent（productionAgent）** 两大工种。本方案只动剧本 Agent。
- 每个大 Agent 内部是**三层协作**：决策层（导演，只指挥不干活、不读工作区）→ 执行层（干活小兵）→ 监督层（监制，A/B/C/D 评级）。
- Skill＝各岗位的「岗位说明书」`.md`，在 `data/skills/`，**改 `.md` 免编译**；改 `src/` 流程逻辑**必须 `yarn build`**。
- 剧本 Agent 现有岗位文件：`script_agent_decision.md`（导演）、`script_execution_skeleton.md`（骨架）、`script_execution_adaptation.md`（改编策略）、`script_execution_script.md`（分集剧本）、`script_agent_supervision.md`（审核）。

**改造目标**：让 toonflow 的剧本 Agent 具备 leon 的方法论能力，而不是另起炉灏。

## 二、边界评估与建议（你要我评估的部分）

> 🧭 **核心结论：toonflow 的三层协作（决策/执行/监督）与你的「主控/执行子 Agent/审查子 Agent」天然同构——所以策略是「增强」而非「重写骨架」。改源码只用在 prompt 表达不了的地方：流程控制、新增执行节点、门禁交互、数据持久化。**

**分层原则（判断某项改动该落在哪）**：
- **能用文字表达的规则/标准/话术** → 写进 `data/skills/*.md`（免编译、低风险、可快速回滚）。红线、审计清单、风格指纹门槛、启发式共创话术原则都属此类。
- **改变「流程怎么走」的** → 才动 `src/agents/`（需编译）。新增执行节点、逐层门禁的交互与确认、P0 修订回环、决策日志持久化属此类。

**建议的改动边界（从小到大，强烈建议按此顺序）**：

| 层级 | 做什么 | 风险 | 是否需编译 |
|---|---|---|---|
| ✅ **允许（优先）**：data/skills | 注入红线 / 审计清单 / 风格指纹 / 启发式共创原则 / L0–L3 分层要求 | 低 | 否 |
| ✅ **允许（核心）**：src 最小增量 | L0–L3 可门禁推进、结构与风格双独立审计、P0 回环、框架决策持久化（具体落点由调研定） | 中 | 是 |
| ⚠️ **审慎**：src 中等改造 | 决策层从「自动倒推」改为「启发式共创四拍循环」的交互编排 | 中高 | 是 |
| 🚫 **不建议**：重写三层骨架 | 推翻决策/执行/监督协作模型另造一套 | 高 | 是 |

> ⚠️ **给自己的护栏**：不要一上来就重构三层协作。你现有方法论 90% 的价值可以先靠 data/skills 落地（Phase 1），真正需要改源码的是「门禁交互 / 新增节点 / P0 回环 / 决策日志」这几处（Phase 2）。别删决策层「导演不自己干活、失败不接管」这类原生护栏。

## 四、分阶段实施方案

**Phase 0 · 调研先行（只读，必做）**：本方案里所有具体落点——文件名、注册点、数据表/字段、节点插入位置——**都是从逆向指南推断的假设，可能与当前代码不符**。一律以 Claude Code 的实际调研为准，凡有冲突先上报、不硬套。Claude Code 必须先摸清实际结构、产出「结构报告 + Phase 2 实现计划」，经我确认后再改代码。

**Phase 1 · data/skills 注入（免编译，先打地基）**：把红线、审计清单、风格指纹、启发式共创原则写进现有岗位说明书。快速见效、低风险，也为 Phase 2 定义好「流程要保障什么」。

**Phase 2 · src 最小流程改造（核心，需编译）**：只给**目标与约束**，具体改哪些文件、怎么改由 Claude Code 依调研自行成案。四个目标——① 让 L0–L3 成为可门禁的分层推进；② 让结构审计与风格审计成为相互独立的两道审计；③ 让判出 P0 能回环修订而非放行；④ 让框架决策（放弃候选+理由+锁定项+门禁记录）可持久化。**前置门禁：Claude Code 须先产出 Phase 2 实现计划并经我确认，才可编码。**

**Phase 3 · 验收与回归**：`yarn lint` + `yarn build` 通过，跑通一次「小说→L0–L3→分集→双审计→P0 回环」全链路，产出对比报告。
